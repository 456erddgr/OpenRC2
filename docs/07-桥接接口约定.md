# 07 · Java ⇄ libetx.so 桥接接口约定（v1，2026-10-31 23:45）

这是 **唯一** 的对接契约。C++ 侧实现这 9 个符号，Java 侧就已经写好了（`app/src/com/rc2/etx/jni/EtxNative.java` + `app/src/com/rc2/etx/ui/NativePanel.java`），
两边各自可独立编译验收。

## 1. so 的落地方式
- 名字固定 **`libetx.so`**，ABI 只有 **arm64-v8a**（RC2 是 lahaina/arm64，armeabi-v7a 不要）。
- 打包路径：APK 根下 `lib/arm64-v8a/libetx.so`。
- Manifest 已置 `android:extractNativeLibs="true"`，所以 **7z 打包时是否压缩都行**，不必做 page-align 的 uncompressed 处理。
- Java 侧 `System.loadLibrary("etx")`，失败时页面显示 `UnsatisfiedLinkError`，不会崩。

## 2. C 侧必须导出的符号（`extern "C"`，全部不能抛异常）
| 符号 | 签名 | 语义 |
|---|---|---|
| `etx_init` | `int etx_init(const char* sdPath)` | 0=成功。`sdPath` 是 App 私有目录下 `/data/user/0/com.rc2.etx/files/sd`（里面放 V15 的 `RADIO/`、`MODELS/`、`THEMES/`…） |
| `etx_shutdown` | `void etx_shutdown(void)` | 释放 |
| `etx_version` | `const char* etx_version(void)` | 返回 `"2.12.2"` 之类 |
| `etx_screen_w` / `etx_screen_h` | `int ...(void)` | LVGL 逻辑分辨率（V15 用 480x272 或 320x480，**由你决定，Java 自适应缩放**） |
| `etx_set_inputs` | `void etx_set_inputs(const int* axes, int nAxes, const int* sw, int nSw, const int* knobs, int nKnobs)` | 见 §3 |
| `etx_tick` | `int etx_tick(int ms)` | 推进 EdgeTX 主循环 ms 毫秒，**返回 1 表示有新画面** |
| `etx_touch` | `int etx_touch(int action, int x, int y)` | action: 0=按下 1=移动 2=抬起，坐标是 **LVGL 逻辑坐标**；返回 1=被消费 |
| `etx_channels_us` | `int etx_channels_us(int* out16)` | 写 16 路 us 值（172..1811），返回写了几个 |
| `etx_render` | `int etx_render(int* argb, int w, int h)` | 把当前帧写进 `argb`（`w*h` 个 0xAARRGGBB），返回 1=有变化 |

## 3. 输入数据约定（和 V15 的 11bit ADC 严格同构）
- **axes**：`int[4]`，顺序 **`{RH, RV, LV, LH}`** —— 这是 **MCU 物理序 ch0..ch3**，不是 EdgeTX 界面上的 LH/LV/RH/RV。
  （0.9.0 实测更正：早先写的 `{LH,LV,RV,RH}` 是错的，按那个传端点只到 82%。证据见 `docs/13`。）
  含义：`axes[0]=右水平(RH/AIL)`、`axes[1]=右竖直(RV/ELE)`、`axes[2]=左竖直(LV/THR)`、`axes[3]=左水平(LH/RUD)`。
  - RC2 实测映射：`LH=RUD(ax3)`、`LV=THR(ax2)`、`RV=ELE(ax1)`、`RH=AIL(ax0)`。
  - 取值范围 **0..2047**，中位 **1024**，满行程 **±660**（端点 364/1684）。这是硬件真值，别改成 0..4095 或 -1024..1024。
- **sw**：`int[4]`，0/1（对应 AUX1..AUX4 的三档开关，当前只取"上"位）；后续扩到 6 路。
- **knobs**：`int[2]`，同 11bit 口径（对应 V15 的 P1/P2；P3 留给以后）。
- 调用频率 **100Hz**，同一个线程（Java 的 UI 线程），C 侧不用加锁。

## 4. 时序/线程/性能预算
- `etx_tick` 每 10ms 一次；`etx_render` 只在 `etx_tick` 返回 1 时调用，30fps 封顶。
- 单帧 `480x272 ARGB8888` = 510KB，`etx_render` 端到端要 **≤15ms**（这是 30fps 的预算）。
- **不要在 C 侧起额外线程**，也不要阻塞 >50ms：整个 App 只有一个 100Hz 控制环，超时会掉帧。
- **不要在 JNI 边界抛 C++ 异常**；出错返回非 0 并 `__android_log_print(ANDROID_LOG_ERROR, "ETX-Native", ...)`。

## 5. 分阶段验收
- **里程碑 2（先做）**：`etx_init` 能读 SD 上的 `RADIO/radio.yml`，`etx_version()` 返回 `2.12.2`，`etx_screen_w/h` 返回非 0，`etx_render` 能画出一张 **纯色 + "EdgeTX 2.12.2" 文字** 的帧（LVGL 只上 `lv_label` 就够）。Java 页上能看到这张图 = 通。
- **里程碑 3**：`etx_set_inputs` → 真 EdgeTX 的 mixer 出通道 → `etx_channels_us` 的 16 路与 Java 自算的混控结果一致（允许 ±3us）。
- **里程碑 4**：LVGL 上完整界面（`radio/src/gui/colorlcd`），触摸能翻页、能进模型设置。

## 6. 已知的坑（我这边踩过，提前告诉你）
- 包名不能叫 `com.rc2.etx.native`——`native` 是 Java 关键字，javac 直接报"需要<标识符>"。已改成 `com.rc2.etx.jni`。
- EdgeTX 的 `radio.yml` 里 `spanNeg` 可能是负数也可能正数，**别先做归一化**，原样打印，等我和 V15 真值对完再定口径。
- `etx_render` 的输出我按 **ARGB_8888 小端 int** 读（`Color.argb` 顺序），不是 RGB565。

## 追加（2026-11-01，真机验证后）

### ABI：必须 armeabi-v7a（32 位）
本 ROM 对新装 App 强制 `abiOverride=armeabi-v7a`（详见 `docs/09-安装期ABI限制.md`）。
所以 `libetx.so` 必须至少提供 `lib/armeabi-v7a/libetx.so`；只有 arm64 的包安装期直接失败。
推荐两个都编（`armeabi-v7a` + `arm64-v8a`），APK 里同时存在更稳。

### 链接参数（缺一不可）
```
-shared -fPIC -O2 -fvisibility=default -static-libstdc++ -llog -Wl,-soname,libetx.so
```
- `-static-libstdc++`：否则 `dlopen failed: library "libc++_shared.so" not found`
- `-llog`：否则 `cannot locate symbol "__android_log_print"`

### JNI 胶水已提供（EdgeTX 侧不用管 JNI）
`app/jniStub/etx_jni.cpp` 导出 9 个 `Java_com_rc2_etx_jni_EtxNative_*`，内部只调 C 符号。
EdgeTX 侧只要保证下面 10 个 C 符号存在且签名一致，胶水直接链进去：
```c
int  etx_init(const char* sdPath);      /* 0=OK, -2=radio.yml 读不到 */
void etx_shutdown(void);
const char* etx_version(void);
int  etx_screen_w(void);
int  etx_screen_h(void);
void etx_set_inputs(const int* axes, int nAxes, const int* sw, int nSw,
                    const int* knobs, int nKnobs);
int  etx_tick(int ms);                  /* 1 = 有新帧 */
int  etx_touch(int action, int x, int y); /* 0 down / 1 move / 2 up */
int  etx_channels_us(int* out16);       /* 返回写了几路 */
int  etx_render(int* argb, int w, int h); /* 1 = 画面变了 */
```

### 真机验收基线（桩 so，v0.6.3 已通过）
`available=true / radio_yml=true / init_rc=0 / render=1 / argb 1346/1346 非零 / channels=16`。
真 so 接上来后这三行必须继续成立，然后才谈"画得像不像 EdgeTX"。

## 2026-11-01 新增：第 10 个导出 `etx_key(int key, int down)`

**原因**：RC2 物理按键只有 `KEY_POWER/KEY_VOLUMEUP/KEY_VOLUMEDOWN`（`getevent -pl` 实测），
没有方向/确认键；EdgeTX colorlcd 的页面栈、菜单、确认框、数字编辑都依赖 `EnumKeys`。
只有 `etx_touch` 会出现"点进去出不来"。

```c
// 返回 1=事件被消费，0=忽略
int etx_key(int key, int down);
```

键码表（与 `EnumKeys` 顺序对齐，实现用查表别散 if）：

| 值 | 含义 | EdgeTX |
|---|---|---|
|0|UP|`KEY_UP`|
|1|DOWN|`KEY_DOWN`|
|2|LEFT|`KEY_LEFT`|
|3|RIGHT|`KEY_RIGHT`|
|4|ENTER|`KEY_ENTER`|
|5|RTN/EXIT|`KEY_EXIT`|
|6|PAGE↑|`KEY_PAGEUP`|
|7|PAGE↓|`KEY_PAGEDN`|
|8|MODEL|`KEY_MODEL`|
|9|TELE|`KEY_TELE`|

约束：
- 走 EdgeTX 自己的事件队列（照 `targets/simu/simpgmspace.cpp` 塞键队列 → `keysPollingCycle()` 消费），
  不要直接调菜单处理函数。
- `down=1/0` 必须成对（EdgeTX 区分短按/长按）。
- 内部队列深度 ≥8，不许覆盖未消费事件。
- 不许阻塞、不许起线程。

## 附录A 上游补充（2026-11-01）：导航地图 / etx_rotary

> 本节由 edgetx-port 追加，只增不改；原契约条目一律以正文为准。

### A.1 第 11 个导出：`void etx_rotary(int steps)`

- `steps > 0` = 顺时针 N 格，`steps < 0` = 逆时针 N 格，`0` = 无操作。
- 语义 = 转动 EdgeTX 的旋转编码器（`ROTARY_ENCODER_GRANULARITY` 一格），不是"方向键"。
- Java 侧把滑动手势映射到这里（`EtxNative.rotary(int)` → JNI `Java_com_rc2_etx_jni_EtxNative_rotary`）。
- 为什么必须单独有它：`targets/horus/board.h:28` 定义了 `ROTARY_ENCODER_NAVIGATION`，
  于是 `gui/colorlcd/LvglWrapper.cpp:255-290` 注册的是 **LVGL encoder indev**，
  读数来自 `rotaryEncoderGetValue()`（`targets/simu/simpgmspace.cpp:59`）。
  **表单/数值域的焦点切换只吃这个编码器**：`KEY_UP/DOWN/LEFT/RIGHT` 与 `PAGEUP/PAGEDN`
  在 Mix 编辑器里实测全部 `draw=0`，焦点不动。

### A.2 `HARDWARE_KEYS` 开/关的区别（构建宏，非运行时）

- 必须开（出处 `radio/src/targets/horus/CMakeLists.txt:181`：
  `add_definitions(-DPCBHORUS -DSTM32F429_439xx -DSTM32F429xx -DSDRAM -DHARDWARE_KEYS)`）。
- **不开的后果**：`libui/window.cpp:505-525` 的 `NavWindow::onEvent` 整段在
  `#if defined(HARDWARE_KEYS)` 内被裁掉 → `PAGEUP/PAGEDN/MODEL/SYS/TELE/长按 RTN`
  全部无反应；表现为"菜单能进、换不了页，所有翻页键 `draw=0`"。
- 开了之后事件码实测：`PAGEUP` → `0x603`（`_MSK_KEY_FIRST 0x0600 | 3`），
  `KEY_RIGHT` → `0x608`（`| 8`）。

### A.3 导航地图（真机实测，键码见正文 0..9）
