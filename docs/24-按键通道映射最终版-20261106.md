# 24 · 物理按键 → 通道 最终映射（2026-11-06）

> 本文是「按键接成通道」这件事的最终结论。
> 前面 `docs/23` 的映射有错（把 C2 认成拍照、把拍照认成录像），以本文为准。

---

## 一、最终映射表（全部单键实测）

`06/AE` 帧载荷位置（payload 从 `0x55` 后第 5 字节算起）：

```
[0]snd=06 [1]rcv=02 [2..3]seq [4]attr [5]cs=06 [6]ci=AE
[7]=k1  [8]=k2  [9]=k3        ← 按键位
[10]保留  [11..] 6×u16 摇杆值（中点 1024，满行程 364/1684）
```

| 物理键 | 判定 | 实测值 |
|---|---|---|
| **C1**（后面自定义键1） | `k3 & 0x04` | 按下 `k3=0x05` / 松开 `0x01` |
| **C2**（后面自定义键2） | `k3 & 0x08` | 按下 `k3=0x09` / 松开 `0x01` |
| **拍照键** | `k1 & 0x40` | 按下 `k1=0x40` |
| **录像键** | `k2 & 0x01` | 按下 `k2=0x01` |
| **调档 S 档** | `k3 & 0x03 == 0` | `k3=0x00` |
| **调档 N 档**（默认） | `k3 & 0x03 == 1` | `k3=0x01` |
| **调档 C 档** | `k3 & 0x03 == 2` | `k3=0x02` |

> ⚠️ `k3` 低两位是**档位编码**，不是"常驻标志"。拨档时它整个替换。
> 早期误以为 `0x02` 是"拨轮中位常驻"，导致档位判定全错。

**用户口径**：N 档 = +100%，C 档 = −100%（这跟"上/下档"直觉相反，已按用户要求实现）。

## 二、通道分配（16 通道，2026-11-06 重排）

用户反馈「通道太乱，按键的在一起、旋钮的在一起」，所以按类别重排：

| 通道 | 源 | 类别 | 说明 |
|---|---|---|---|
| CH01-04 | AIL/ELV/THR/RUD | 摇杆 | 四轴 |
| **CH05-06** | K1/K2 | 旋钮 | |
| **CH07** | AUX2 | 按键 | **C1**（后面自定义键1） |
| **CH08** | AUX3 | 按键 | **C2**（后面自定义键2） |
| **CH09** | SW_SHOT | 按键 | **拍照键** |
| **CH10** | SW_REC | 按键 | **录像键** |
| **CH11** | AUX1 | 档位 | **调档主**：N=+100% / C=−100% / S=0% |
| **CH12** | SW_S | 档位 | **调档S**：S 档时 +100% |
| **CH13** | SW_C | 档位 | **调档C**：C 档时 +100% |
| CH14-16 | 未使用 | | |

### 三档实测（截图验证通过）

| 档位 | CH11 调档主 | CH12 调档S | CH13 调档C |
|---|---|---|---|
| **N 档**（默认） | **+100%** | −100% | −100% |
| **C 档** | −100% | −100% | **+100%** |
| **S 档** | 0% | **+100%** | −100% |

### 修掉的重复

用户报「录像键和 AUX4 重合，按录像键两个通道一起动」。

原因：`Radio.tick()` 里 `input.aux4` 被赋值**两次** ——
第一次写拍照、第二次被录像覆盖，等于两个键抢同一个槽；
同时 CH09/CH10 已经有独立源，所以一按键就出现「两个通道一起变」。

修法：`input.aux4 = 0f`，不再承担按键；按键一律走 `SRC_SW_*` 独立源。

## 三、修掉的三个真 bug

### 3.1 四个开关一直 −100%（第一次误判）

一开始以为是 `axes7[6]=0` 和 `potOrMin` 返回 0。改了之后 CH05 确实变了 ——
但那是巧合，因为它同时接了 AUX1。

**真正的原因**：通道页的数值来自 `mixer.compute(input)`，读的是 `input.aux1..aux4`，
而全代码里**从来没有** `input.touch(4..7)` —— aux 一直是 `reset()` 的 `-1f`，
混控就把它算成 −1024 → 显示 −100%。

修法：在控制环（`Radio.tick()`）里直接写 `input.aux1..aux4`，不走 `touch()`（避免被摇杆校准污染）。

### 3.2 调档键判定错

原来 `gearPos()` 用 `k3 & 0x03` 但把 `0x01` 当成"常驻位"掩掉了，
于是 H 档被判成无效，S/C 也判错。

修法：老老实实把低两位当档位编码 —— 0=S、1=N/H、2=C。

### 3.3 物理键会触发 EdgeTX 自己的界面（用户最关键的一条反馈）

**现象**：按拍照键 → EdgeTX 跳到「通道查看」；按录像键 → 跳到「模型设置」；
拨旋钮 → EdgeTX 以为在拖 UI 滑块。

**原因**：`applyRcProButtons()` 里把物理键翻译成了 EdgeTX 按键事件：

```java
// 拍照 → PROBE_KEY_SHOT (=9, TELE=通道查看)
// 录像 → PROBE_KEY_REC (=8, MODEL=模型设置)
// 五维方向 → nav 0..5（UP/DOWN/LEFT/RIGHT/ENTER/EXIT）
```

**修法**：加开关 `ENABLE_KEY_INJECT = false`，把两段注入整块包起来。
物理键从此**只产生通道值**，不再碰 EdgeTX 界面。

> 这条是本轮最重要的修复 —— 前面所有"通道对了"的努力，
> 在这个问题存在时都会被"按键顺带把界面搞乱"抵消掉。

## 六、高频摇杆：本轮把所有可能的路都试过了，全部排除

用户反复要求「找 22Hz 的高频摇杆」。下面是本轮的完整排查，**每条都实测过**。

### 已排除（6 条）

| # | 通路 | 实测结果 | 结论 |
|---|---|---|---|
| 1 | TCP `40007` | `stickHz=9~10`，`lost=0 gapN=0`（seq 连续无跳号） | **10Hz 是硬上限**，不是我们漏帧 |
| 2 | TCP `40009` | 独占 30s 收 10 帧，全是 1024 占位 | 死值 |
| 3 | binder `transact(4)` | 60Hz 回包，但 `changeHz=0`（连采 30 分钟一次没变） | 纯请求-应答，值是假的 |
| 4 | TCP `8902` | 593 包/秒（唯一真高频流） | 是**图传**（`dji_sdrs_agent`），不含摇杆 |
| 5 | unix socket `/dev/socket/fpv_sock` | 能连上，但**服务端 0 字节**；试了 4 种种子包都没回 | 不推送 |
| 6 | 串口 `/dev/ttyHS3` | 能打开，读 5 秒 **0 字节**（被 dji_link 独占） | 拿不到 |

### 还没试的（1 条）

| 通路 | 说明 | 风险 |
|---|---|---|
| USB 端点直接抢读 | `/dev/bus/usb/002/006`，接口 `2-1:1.0` = **"MA Channel"**，Bulk IN 端点 `0x81`。`dji_link` 正独占这个端点读数据。root 下可以同时打开并 submit URB 抢读 | **高**：会和 `dji_link` 抢数据，可能导致摇杆断连、甚至链路异常。不保证成功，抢到的也可能是同一份 10Hz 数据 |

### 诚实结论

**目前没有找到比 10Hz 更快的摇杆数据源。**

别人说的 "22Hz" 最可能是：
1. 在 10Hz 真值上做插值（我们已经做到 100Hz 控制 / 250Hz 推流），"22Hz" 只是他们的输出帧率
2. 或者他们用的是我们还没找到的订阅入口

**如果要继续追**，唯一还剩的路是第 7 条（USB 端点抢读），需要你确认是否接受断连风险。

## 七、原生核心只有 4 个开关位置（C/S 档进不去的原因）

用户反馈「外面通道页能看到 C 档和 S 档，但移植系统内部没有」。

**原因**：EdgeTX 的板级 HAL 只提供 4 个开关（SA/SB/SC/SD）：

```cpp
// RC2-EdgeTX-Native/src/hal/etx_hal_misc.cpp
static const char* names[4] = {"SA", "SB", "SC", "SD"};
SwitchHwType boardSwitchGetType(uint8_t) { return SWITCH_HW_3POS; }
SwitchHwPos boardSwitchGetPosition(uint8_t idx)  // 只能返回 UP/MID/DOWN
```

Java 侧 `EtxNative.setInputs(axes, 7, sw, 4, ...)` 也只送 4 个。

所以：
- **Java 混控器（通道页）** 能任意加通道，所以 CH11-CH13 都看得见
- **原生 EdgeTX 核心** 只认 SA-SD 四个开关，没有第 5 个槽位

**要解决必须改原生**：在 `etx_hal_misc.cpp` 里把开关数量从 4 扩到 6~8，
并让 `boardSwitchGetPosition()` 能读第 5/6 个。这需要重编 `libetx.so`。

### 现在原生侧能拿到什么

| 原生开关 | 映射 | 说明 |
|---|---|---|
| SA | 调档键（N=UP / S=MID / C=DOWN） | 三档正好对应 |
| SB | C1 | 两态（UP/DOWN） |
| SC | C2 | 两态 |
| SD | 拍照 | 两态 |

**录像键目前没有原生槽位。**
