# 24 · 物理按键 → 通道 最终映射（2026-11-06）

> 本文是「按键接成通道」这件事的最终结论。
> 前面 `docs/23` 的映射有错（把 C2 认成拍照、把拍照认成录像），以本文为准。

---

## 一、最终映射表（全部单键实测）

`06/AE` 帧载荷位置（payload 从 `0x55` 后第 5 字节算起）：

```
[0]snd=06 [1]rcv=02 [2..3]seq [4]attr [5]cs=06 [6]ci=AE
[7]=k1  [8]=k2  [9]=k3        ← 按键位
[10]保留  [11..] 6×u16 摇杆值（中点 1024，满行程 364/1684）
```

| 物理键 | 判定 | 实测值 |
|---|---|---|
| **C1**（后面自定义键1） | `k3 & 0x04` | 按下 `k3=0x05` / 松开 `0x01` |
| **C2**（后面自定义键2） | `k3 & 0x08` | 按下 `k3=0x09` / 松开 `0x01` |
| **拍照键** | `k1 & 0x40` | 按下 `k1=0x40` |
| **录像键** | `k2 & 0x01` | 按下 `k2=0x01` |
| **调档 S 档** | `k3 & 0x03 == 0` | `k3=0x00` |
| **调档 N 档**（默认） | `k3 & 0x03 == 1` | `k3=0x01` |
| **调档 C 档** | `k3 & 0x03 == 2` | `k3=0x02` |

> ⚠️ `k3` 低两位是**档位编码**，不是"常驻标志"。拨档时它整个替换。
> 早期误以为 `0x02` 是"拨轮中位常驻"，导致档位判定全错。

**用户口径**：N 档 = +100%，C 档 = −100%（这跟"上/下档"直觉相反，已按用户要求实现）。

## 三、修掉的三个真 bug

### 3.1 四个开关一直 −100%（第一次误判）

一开始以为是 `axes7[6]=0` 和 `potOrMin` 返回 0。改了之后 CH05 确实变了 ——
但那是巧合，因为它同时接了 AUX1。

**真正的原因**：通道页的数值来自 `mixer.compute(input)`，读的是 `input.aux1..aux4`，
而全代码里**从来没有** `input.touch(4..7)` —— aux 一直是 `reset()` 的 `-1f`，
混控就把它算成 −1024 → 显示 −100%。

修法：在控制环（`Radio.tick()`）里直接写 `input.aux1..aux4`，不走 `touch()`（避免被摇杆校准污染）。

### 3.2 调档键判定错

原来 `gearPos()` 用 `k3 & 0x03` 但把 `0x01` 当成"常驻位"掩掉了，
于是 H 档被判成无效，S/C 也判错。

修法：老老实实把低两位当档位编码 —— 0=S、1=N/H、2=C。

### 3.3 物理键会触发 EdgeTX 自己的界面（用户最关键的一条反馈）

**现象**：按拍照键 → EdgeTX 跳到「通道查看」；按录像键 → 跳到「模型设置」；
拨旋钮 → EdgeTX 以为在拖 UI 滑块。

**原因**：`applyRcProButtons()` 里把物理键翻译成了 EdgeTX 按键事件：

```java
// 拍照 → PROBE_KEY_SHOT (=9, TELE=通道查看)
// 录像 → PROBE_KEY_REC (=8, MODEL=模型设置)
// 五维方向 → nav 0..5（UP/DOWN/LEFT/RIGHT/ENTER/EXIT）
```

**修法**：加开关 `ENABLE_KEY_INJECT = false`，把两段注入整块包起来。
物理键从此**只产生通道值**，不再碰 EdgeTX 界面。

> 这条是本轮最重要的修复 —— 前面所有"通道对了"的努力，
> 在这个问题存在时都会被"按键顺带把界面搞乱"抵消掉。
