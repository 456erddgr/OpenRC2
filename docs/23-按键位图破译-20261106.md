## 一、结论：`06/AE` 帧的 [7][8][9] 三个字节就是按键位图

```
载荷布局（payload 从 0x55 之后第 5 字节起）：
  [0] snd=0x06   [1] rcv=0x02   [2..3] seq(LE)   [4] attr
  [5] cmd_set=0x06   [6] cmd_id=0xAE
  [7][8][9]  ← 按键位图（三个字节）
  [10] 保留
  [11..22] 6×u16 LE 摇杆值（中点 1024）
```

### 实测对照表（差分测试，用户按指定键）

| 场景 | k1=[7] | k2=[8] | k3=[9] | 文字 |
|---|---|---|---|---|
| 静止（基线） | `00` | `00` | `02` | 无 |
| 后面自定义键 B | `00` | `00` | `06` | `0x02\|0x04`，新增位 **0x04** |
| 前面 **拍照**键 | `00` | `00` | `0A` | `0x02\|0x08`，新增位 **0x08** |
| 前面 **录像**键 | `00` | `01` | `02` | k2 的 **0x01** |
| 前面 **录像**键（另一相） | `40` | `00` | `02` | k1 的 **0x40** |
| 后面键 B + 拍照同时 | `00` | `00` | `0E` | `0x02\|0x04\|0x08` |

**掩码规则**：
- `k3` 的 `0x02` = 拨轮在中位的常驻值，**不是按键**，判定时要掩掉
- `k3` 的 `0x01` 也是常驻（出现在 `0x03`/`0x09` 这类值里），一并掩掉

代码实现（`DumlStick.hasKey` / `decodeKeys`）：

```java
public static boolean hasKey(int k1, int k2, int k3) {
    return (k1 & 0x40) != 0 || (k2 & 0x01) != 0 || (k3 & 0xFC) != 0;
}
```

## 二、怎么找到的（方法比结论更值钱）

前两次尝试都**失败**了，原因值得记下来。

### 第一次失败：只看"帧型出没出现"

用「载荷变化种类」排序，得到 `06/84`=16、`18/40`=41 等一堆"高变化"帧型。
但**这些帧在完全不碰遥控器时也在变** —— 它们是心跳/计数器。

**教训**：帧型"有变化"不等于"按键引起"。

### 第二次失败：用静默基线做集合差

采 20 秒静默基线，把所有 `(帧型|载荷)` 收进集合，再采按键窗口，只报"集合里没有的"。

结果：后面键 A 报了 **200 种新载荷** —— 全是心跳帧的时间戳/序号变了。

**教训**：带自增序号或时间戳的帧，每次载荷都不同，集合差方法会把它们全部当成"新"。

### 第三次成功：按帧型的「基线稳定性」过滤

关键改动：**先统计每个帧型在静默基线期间出现过几种载荷**，
只保留「基线里载荷种类 ≤ 3」的帧型（说明这类帧平时很稳定），
再在这些帧型里做差分。

基线结果（20 秒，什么都没碰）：

| 帧型 | 基线载荷种类 | 判定 |
|---|---|---|
| `00/F1` | 1 | 稳定 ✓ |
| `EE/0C` | 2 | 稳定 ✓ |
| **`06/AE`** | **1** | **稳定 ✓ ← 摇杆帧，按键位就在这** |
| `00/76` | 1 | 稳定 ✓ |
| `00/77` | 1 | 稳定 ✓ |
| `09/11` | 1 | 稳定 ✓ |
| `06/1E` | 15 | 抖动 ✗ |
| `18/40` | 41 | 抖动 ✗ |
| `09/43` | 40 | 抖动 ✗ |
| `06/84` | 40 | 抖动 ✗ |
| `00/81` | 21 | 抖动 ✗ |
| `09/08` | 20 | 抖动 ✗ |
| `09/75` | 20 | 抖动 ✗ |
| `09/36` | 10 | 抖动 ✗ |

**过滤后只剩 6 个帧型**，按键一按，`06/AE` 立刻冒出 `00000500` / `00000900` —— 一眼就看出来了。

## 三、其余帧型的意义（顺带发现）

| 帧型 | 实测行为 | 推测含义 |
|---|---|---|
| `09/11` | 每次按键出现**一条新载荷** `0e02 XXXX 0009 11 03`，XXXX 自增 | 「有键被按下」的广播/序号 |
| `EE/0C` | 成对出现：`...0001`（按下）→ `...0000`（松开），序号自增 | 按键的 down/up 事件对 |
| `00/76` | **JSON 明文**（见下） | 固件事件总线上报 |

`00/76` 解出来的 JSON：

```json
{"event_id":"fw_0e07_wlm_gnd_rpt_cycle","P0":45,"P1":1,"P2":2,"P3":4,"P4":3,"F13":0,"F14":0}
```

三次按键依次是 `P0=45 / 46 / 47`，是**事件序号**，不是键值。
但这是好消息：**这台机器的固件会以明文 JSON 上报事件**，以后要找别的功能（比如飞行状态），
可以优先盯着 `00/76`。

## 四、还没解出来的

| 项 | 状态 |
|---|---|
| **后面自定义键 A（左边）** | 差分只测到 1 种新载荷 `09/11`（广播），**没拿到独立位**。可能 A 和 B 共用位，或 A 走别的路径 |
| **前面切换档位键** | 同样只测到 `09/11` 广播，没有独立位。可能它是三档开关，需要按"位置"读而不是"边沿" |
| 拨轮 | `k3=0x02` 是中位常驻；左右拨到底时 `06/AE` 的**摇杆值区**（[11..22] 末尾两个 u16）在变，说明拨轮走的是模拟量，不是位图 |

## 六、一个要记住的教训

这轮我在改 `DumlStick.java` 时**误删了 486 行**（用 Python 做字符串替换时，
`start`/`end` 锚点选得太大，把中间的 `setAxisSpans` / `stickFresh` / 差分模块全吃掉了）。
编译报了 20 多个"找不到符号"，我才发现。

**恢复办法**：`git checkout -- <file>` 回到上一个提交，然后用**最小 edit** 重做一遍。

**教训**：
1. 用脚本做大范围字符串替换前，先 `git diff --stat` 看改动行数是否合理
2. 优先用 `edit` 工具做定点替换，不用整段切片
3. 改完立刻 `bash scripts/build-apk.sh <ver>`，编译错误比运行时错误好查得多
