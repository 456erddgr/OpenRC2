## 2. 修复一：「模型管理」闪退 + 列表空白（用户抱怨最多的那条）

### 2.1 现象
- 点「模型管理」（EdgeTX 的 `ModelLabelsWindow`）→ 约 20 秒后进程死掉，被看门狗重启；
- 页面本身能画出来，但列表区全空、副标题显示「当前模型: 无效」。

### 2.2 崩溃证据（设备端 `/sdcard/Android/data/com.rc2.etx/files/sd/crash_native.txt`）
```
signal 11 addr 0x10 pc 0xcacbf4b8 base 0xca782000 off 0x43d4b8 time 1793709803
signal 6  addr 0x5d3f pc 0xeb03cee0 base 0xeb004000 off 0x38ee0  time 1793709803
```
`off 0x43d4b8` 用 `llvm-addr2line` / `llvm-nm` 定位到：
```
0x43d430  std::__ndk1::set<unsigned int, ...>::insert[abi:v170000](...)
0x43d32c  ListBox::~ListBox()
0x43d1c4  ListBox::onDrawEnd(...)
0x43d524  std::__ndk1::__tree<unsigned int, ...>::__find_equal(...)
```
`addr 0x10` = 访问了 `std::set` 内部的 `this->_M_header._M_parent`（结构体偏移 0x10 处的空指针）——典型的**在未构造/已清零的 `std::set` 上做 insert/拷贝**。

### 2.3 根因（两条，互相叠加）
1. **全局 BSS 被整段清零**：真机实测 `modelslist` 在启动后约 70 ms 从 `size()==1` 变成 `0`，
   且 `modelslist` 对象自身的 12 字节（vector 的三个指针）也全变 `0x00` —— 说明**不是 `clear()` 清的**，是外部 memset 覆盖。
   实测被清零的连续区间长 **1888 字节**，范围覆盖 `s_anaFilt` / `modelslist` / `modelslabels` / `ModelMap::filtlblsRef()::s` / `g_FATFS_Obj` / `_module_states` 等。
   （`ModelsList::clear()` 已加日志探针，确认掉到 0 时**没有** `CLEAR` 记录。）
   > 这个「谁在 memset」本轮**没有查到底**（设备掉线，无法继续二分）。属于遗留项。
2. **空标签表导致无符号下溢**：`ModelLabelsWindow` 构造里
   `lblselector->setSelected(getLabels().size() - 1);`，当标签表为空时 `size()-1` 下溢成 `0xFFFFFFFF`，
   随后在 `std::set<uint32_t>` 上做插入/拷贝 → 崩在 2.2 那个位置。这条是 **1 的直接后果**，但也是**必须独立修的防御点**。

### 2.4 修复（两条都做了）
**A. 原生防御补丁** —— `RC2-EdgeTX-Native/vendor/edgetx-src-2.12.2/radio/src/gui/colorlcd/model/model_select.cpp`
- `ModelLabelsWindow` 构造开头：若 `modelslist.size()==0` 就先 `clear()` + `load()` 重建一次；
- 构造末尾：若 `getLabels().empty()`，跳过「选中第一个标签」那段，直接 `enableRefresh(); return;`
  —— 彻底消除 `size()-1` 下溢。

**B. 运行时自愈探针** —— 新增 `RC2-EdgeTX-Native/src/ui/etx_store_diag.cpp`
- `etx_store_diag()`：打印 `sdMounted / models / labels / curr / curptr / labelsStat / opendir / entries`
- `etx_store_watch()`：每帧调用，仅在「模型数/标签数/当前模型指针」变化时打一行；
  检测到「模型库空但 SD 上确有模型」就自动 `clear()+load()` 重建，**2 秒节流**防抖动。
- `rc2_store_cleared()`：`ModelsList::clear()` 里的回调（vendored 源码挂了 extern 声明），带调用栈。

### 2.5 验证到什么程度
- ✅ 静态验证：`model_select.o` 新增引用 `ModelsList::load()` / `ModelsList::clear()`；
  最终 so 里 `ModelLabelsWindow`（0x490880）在 +0x78/+0x84 处两条 `bl` 经 PLT veneer
  （`0x62e940` / `0x62e9a0`）→ GOT `0x66a73c` / `0x66a754` → `ModelsList::load()` 0x3d8060 / `clear()` 0x3d8004。
- ✅ 运行时验证（**打补丁前**的版本上）：`AUTO-REPAIR` 确实能触发并把 `models` 从 0 恢复成 1。
- ❌ **未验证**：打补丁后的 1.46.43 上，打开「模型管理」是否还崩、列表是否正常显示 —— 设备掉线，没跑。

## 3. 修复二：RC Pro 六轴全 −100% + 旁键不可用

详见 `19-rcpro-修复记录.md`。摘要：

| # | 根因 | 修复文件 |
|---|---|---|
| 1 | `stickSourceAlive()` 用 `duml.connected` 判活，RC Pro 的 40007 连一次就 EOF ⇒ 恒 false ⇒ 不喂混控、走 synth 假值（−100%）、`applyRcProButtons()` 整段不执行 | `radio/Radio.java`（仅 3 处） |
| 2 | `DumlStick` 快照模式重连间隔注释写 10 ms、代码却是 **5000 ms**（0.2 Hz） | `input/DumlStick.java` |
| 3 | `RcProStick.raw` 初值全 0，经 `(0−1024)/660` 正好 = 每轴 −100%，是「载荷没解析出来」的伪装 | `input/RcProStick.java` |
| 4 | 旁键数据要另走 binder `06/174` 帧 | `input/RcProService.java` |

关键设计：判活改用**单调时钟** `SystemClock.elapsedRealtime()`（不用 `currentTimeMillis`——会被对时跳变；
不用 `uptimeMillis`——深度休眠停走），判据 `d = now - last; return d >= 0 && d < ms;`（`d>=0` 防下溢）。

⚠️ **未真机验证**（RC Pro 从未接入本轮设备）。

## 4. 修复三：RC Plus2 兼容 + 物理按键

详见 `18-rcplus2-兼容分析.md`。摘要：
- 参照包 `Plus2 Xbox手柄_1.0.apk.1` 读 RC Plus2 走的是**和 RC Pro 同一套 DJI binder**
  （`getService("protocol")` → `IProtocolManager` → `transact(4)`），我们的 `RcProService` 传输层**逐字节兼容**；
- 轴序（已被 `RCPro-资料/d3` 源码证实）：`ch3→lx`、`ch2→−ly`、`ch0→rx`、`ch1→−ry`、`ch4/ch5 = 左/右波轮（双向，中位 1024）`；
- **物理按键不走 binder**：它们在内核里是普通输入设备事件，只有 `AccessibilityService.onKeyEvent` 拿得到。

### 4.1 新增（本轮落地）
| 文件 | 作用 |
|---|---|
| `app/src/com/rc2/etx/input/KeysService.java`（新） | AccessibilityService，`onKeyEvent` → `EtxNative.press/release` |
| `app/res/xml/accessibility.xml`（新） | `canRequestFilterKeyEvents="true"` + `flagRequestFilterKeyEvents` |
| `app/AndroidManifest.xml` | 注册 `<service android:name=".input.KeysService">`（**绝对不能加 `android:process`**） |
| `app/src/com/rc2/etx/MainActivity.java` | 新增 `--es action a11y`，跳系统无障碍设置页 |

### 4.2 铁律（新增，别违反）
1. **`KeysService` 必须与 libetx 同进程** —— 绝不给它加 `android:process`。
   理由：`EtxNative` 状态是进程内的，换进程 = 加载一份空核心，按了没人看见。
2. **原生按键队列 `s_keyq`（`src/etx_api.cpp`）没有锁** —— 若以后把 `EtxNative.tick()` 挪出主线程，
   必须同步给它加锁。当前 tick 在 Java 主线程、无障碍回调也在主线程，天然串行。
3. RC2 实测**没有**任何叫 "DJI" 的输入设备（只有 `himax-touchscreen` / `qpnp_pon` / `gpio-keys`），
   `gpio-keys.kl` 只有 5 个键 ⇒ 这套服务在 RC2 上只能命中 CAMERA 一个键，**真实目标是 RC Plus 2**。

### 4.3 未验证
`dumpsys accessibility` 是否注册、`onKeyEvent` 是否触发 —— 全部未跑。

## 5. 构建脚本加固（本轮新增）

`scripts/build-apk.sh` 加两道防线，因为踩过「重链后忘同步 so，静默用旧 so 出包」的坑：
1. 每次构建打印 `keep/libetx.so` 的 **mtime + sha16**；
2. 若 `RC2-EdgeTX-Native/out/libetx/libetx.so` 比 `keep/libetx.so` **新**，直接
   `[FATAL] ... 重链后忘了同步` 并退出，同时打印该执行的 `cp`。

4. ~~**【P1】`Radio.java` 时钟混用 bug**~~ —— **已修（1.46.44）**。
   原问题：`tick()` 用 `elapsedRealtime()`，而桥线程写 `lastBinderMs = currentTimeMillis()`，
   两者相减约 −1.7e12 ⇒ `binderFresh` 恒为 true（每 20 ms 空转，不影响数值但白耗 CPU）。

   `now2`（`currentTimeMillis`）保留给 `duml.lastStickMs` 比较那处不动。
