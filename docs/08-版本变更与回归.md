## 1.7.1 / 1.7.2（2026-11-01 05:3x）按键投递抖动是真问题，已根治

### 1.18.3 两次内核崩溃的真因与最终修法（重要）
用户报"选游戏手柄后卡一下 → 请求 root → 重启"，以及后续"还原 USB 也重启"。逐项定位到**两个独立的崩溃触发点**：

1. **抢 Apple 的 UDC**：旧脚本直接 `: > /config/usb_gadget/g1/UDC`，而此刻 adbd/MTP 的 ffs 仍持有 fd
   → 内核在 UDC 摘除路径上崩 → 整机重启。
   修法：先 `setprop sys.usb.config none` 让 Android **自己**干净摘除（实测 `state` 变 `not attached`，不重启），再去绑我们的 gadget。
2. **在 fd 打开时拆自己的 gadget**：App 已 `open("/dev/hidg0")` 并持续写报文，此时脚本 `: > etxjoy/UDC`
   → 同样在 UDC 摘除路径上崩 → 重启。这是用户第二次报"还原也重启"的原因。
   修法（顺序是硬约束）：
   - 启用：`if (!hasHidNode()) setup();` → 再 `open()`（**已有 hidg0 就绝不重建**，脚本里也加了 `[ -c /dev/hidg0 ] && exit 0` 双保险）
   - 关闭：`hid.close()` → `Thread.sleep(150)` → `restore()`
3. 脚本本身也加 `sleep 1`（unbind 之后再 `setprop mtp,adb`）。

**真机验证（1.18.3，同一台未重启）**：
- 启用：`state=configured`、`hid.txt = on=true|open=true|reports=74|err=-`、Windows `Get-PnpDevice` 出现 `USB\VID_1209&PID_4F54` + `HID-compliant game controller`；
- 关闭：`uptime` 未变（**未重启**）、`getprop sys.usb.config = mtp,adb`、`adb devices` 里 USB 与 WiFi 两路都在。

### 无 root 用户的路径（用户明确要求）
App **不再自动调用 su**（这个 ROM 上 su 会弹授权框，且失败路径不可控）。三选项选中"游戏手柄"时：
- 若 `/dev/hidg0` 已存在 → 直接进入手柄模式（**不需要 root**）；
- 若不存在 → 弹「把遥控器变成 USB 游戏手柄」说明框，给出两条路：
  ① 双击 `pc/RC2-USB手柄-开启.bat`（电脑需能 `adb devices` 看到设备）；
  ② `adb shell su -c sh /data/local/tmp/usbjoy/setup.sh`；
  框里还有「仍要尝试 root 执行」按钮，给愿意授权的人用。
- 对应还原：`pc/RC2-USB手柄-还原.bat`。
- **诚实结论**：Android 上把设备变成 HID 手柄必须写 `/config/usb_gadget`，那是 root-only 分区；
  没有 root 的设备**做不到**，只能走 ① 由电脑一次性 adb 代劳，或 ② 用本软件的 UDP/CRSF 输出 + 电脑端 vJoy 桥。
